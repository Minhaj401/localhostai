# localhost.ai — visual story options

All options retain the confirmed 120-second, 1920×1080 brief: graphics-led
explanation for the first half, recreated UI demo for the second half,
English narration and captions, and the existing black/green brand.

## A — Make room (recommended)

**Device:** one model that needs more memory. **Form:** one growing diagram
that turns into the exact UI workflow.

A model's 28 layers meet a laptop's safe capacity; three layers remain outside.
The phone takes that remainder, and the viewer then performs the same setup in
the recreated app. The viewer understands the reason for every click.

**First two seconds:** a large laptop memory bay fills with layer blocks;
three blocks remain visibly outside it, beneath “Where do the extra layers go?”

**Beats:** model does not fit → laptop coordinates → phone joins → reserve
memory → place 25 + 3 example layers → trace a request → pair in the UI →
choose the model → enable sharing → preview and load → receive a reply.

**Look:** black technical workspace, large white device outlines, green active
layers and paths, Outfit headings and JetBrains Mono labels. The diagram's
layer strip becomes the compute-pool visualization during the UI handoff.

**Sound:** calm explanatory English narration and captions; no music or SFX.

## B — Follow one prompt

**Device:** one sentence travelling through the system. **Form:** an
object-to-object chain led by a single green request marker.

An example question leaves the phone, reaches the laptop, crosses the assigned
model layers and returns as an answer. The second half recreates the setup
needed to send that same question from Chat.

**First two seconds:** “Explain local AI” appears as a large message attached
to a phone, with its route toward a recognizable laptop beginning to draw.

**Beats:** question → local coordinator → split model → phone's assigned
layers → returning answer → recreate pairing and sharing → send the same
question in Chat → the answer arrives.

**Look:** the same black/green brand, but the request marker carries the eye
through large branching routes and then becomes the app's send action.

**Sound:** conversational English narration and captions; no music or SFX.

## C — Open the machine

**Device:** an exploded laptop-and-phone model. **Form:** a cutaway tour from
the inside of the system to its outside controls.

Large cutaway devices reveal distinct weights, context memory, and CPU work.
The components assemble into a working system, then their outer screens become
the recreated app and terminal. This is the most visually ambitious direction.

**First two seconds:** a model-layer slab descends toward a cutaway laptop;
the phone opens beside it to reveal its available memory.

**Beats:** open laptop → reveal CPU and memory → bring in the phone worker →
partition the layer stack → show a token travelling through the machine →
close the devices into their interfaces → perform the demo → answer in Chat.

**Look:** black/green engineering cutaways with restrained 2.5D depth and
large labelled parts, followed by front-facing, readable product screens.

**Sound:** measured technical English narration and captions; no music or SFX.

## Grounding

- The 28-layer, 25+3 placement is a labelled example from the recorded Qwen 2.5
  7B run; it is not a universal split or a benchmark.
- Placement uses safe memory and reachable workers. Phone sharing is opt-in.
- Model state cannot survive a worker restart without reloading.
- The UI is explicitly recreated from current project code and labelled demo.
